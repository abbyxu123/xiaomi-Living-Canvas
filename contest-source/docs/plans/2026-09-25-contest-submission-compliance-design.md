# Living Canvas 赛事提交合规整理设计

日期：2026-09-25

## 目标

在不夸大板端完成度的前提下，把 Living Canvas 的代码、测试、Gemini-S1 适配证据和赛事说明整理为可审核、可复现、符合 AI 硬件赛道要求的提交，并更新现有 PR #1。

## 对外技术口径

- Gemini-S1/openvela 是正式目标平台；应用源码、manifest 映射、ai_agent 安全桥接、LVGL 界面、状态机、后端和自定义 Skill 均以此路线组织。
- 已完成的构建、封装、设备识别、麦克风、FEL 与 SPI NAND 检查按证据逐项陈述。
- Gemini-S1 首次持久化写入以及显示、音频、网络和 ai_agent 的板端端到端运行仍处于平台适配阶段，不表述为已经完成。
- ESP32-S3 仅是辅助交互原型，用于验证界面、触摸与产品流程，不作为 openvela 板端运行证据，也不在项目摘要中突出。
- 公开材料只保留赛事相关、可验证且经过脱敏的工程事实；账号凭据、绝对私人路径、原始固件和 NAND 备份不进入仓库。

## 赛事要求映射

1. **openvela + ai_agent**：团队 manifest 将应用映射到 openvela 构建树，受限桥接把模型结果转换为本地可校验的候选动作。
2. **自定义 Skill**：`dinner-assistant.md` 按 ai_agent 官方格式定义触发、追问、候选数量和安全边界，目标部署到 `/data/agent/skills/`，并提供独立演示步骤。
3. **主动感知与执行**：存在事件触发问候；用户明确确认后，系统才允许灯光意图和可删除偏好记忆等受限动作。
4. **端云协同**：设备端承担状态机、约束复核、确认和 UI；独立后端承担候选生成、会话和手机交接；离线时有确定性回退。
5. **记忆与互联**：临时意愿与长期偏好分离；长期偏好可查看、纠正和删除；手机交接保持同一会话。
6. **LVGL 界面**：自定义状态、角色反馈和确认界面已经纳入目标构建，真机显示验证仍以 Gemini-S1 后续证据为准。

## 证据分层

- `已验证`：主机测试、后端测试、目标构建、镜像封装、只读设备识别、麦克风、FEL/SPI NAND 识别。
- `已实现待板端验证`：LVGL、音频、网络和 ai_agent 的 Gemini-S1 运行时链路。
- `未纳入本次承诺`：尚未接入或没有真实证据的传感器与外设。

所有证据文件只保留命令类别、退出状态、摘要、校验值和结论；不提交二进制镜像、私有目录和敏感内容。
