# Living Canvas ESP32-S3 正式媒体与语音设计

## 目标

把现有保底版升级为可以现场操作的正式流程，同时保持 UI 可替换：待机只循环新 `Circle video.mp4`；唤醒后只显示 `newnew-sitting.png` 主视觉；桌面上的外卖袋、盲盒、米饭是仅有的三个主按钮。第一次点击原位高亮，第二次点击确认。

## 主视觉与交互

- 待机动画转换为 368×448 JPEG 帧序列，目标 10 FPS、质量 70；不再使用低帧率全屏 RGB565 动画。
- 静态菜单保留为 RGB565，确保唤醒瞬间显示。选择态由 `takeout.png`、`mixbox.png`、`eatathome.png` 在原位置合成发光效果，并预生成三张选择帧。
- 菜单只在默认、外卖高亮、盲盒高亮、在家做饭高亮四张画面之间切换，不出现其他旧流程图片。
- 第二次点击同一按钮才进入功能；点击另一个按钮只切换高亮；左上角返回取消。

## 真实语音顺序

外卖和在家做饭确认后进入真实录音：

1. 初始化板载 ES8311 和 16 kHz、16-bit、双声道 I2S。
2. 屏幕显示录音状态，用户说出人数、口味、预算、配送时间或冰箱食材。
3. 再点屏幕可提前结束；最长录音 10 秒。
4. 将双声道混成单声道 PCM，通过 HTTP 上传到 Living Canvas 本地网关。
5. 网关在线时轮询会话状态，进入分析页，再显示推荐和二维码。
6. 网关离线或上传失败时显示明确的重试页，不用预设结果冒充真实识别。

盲盒保留当前简易四选一流程；UI 后续可替换，不阻塞本次主功能。

## 软件边界

- ESP32 工程继续保持独立 Git 历史，不修改 Gemini-S1/openvela 工程。
- 仅复用已经验证过的 ES8311 硬件初始化、I2S 录音参数和通用 `/v1/session`、`/v1/voice` 会话契约。
- 固件、界面、设备名称和资源中只使用 Living Canvas 命名。
- Wi-Fi 密码和本地网关地址放在被 Git 忽略的 `living_canvas_local_config.h`，不会提交。

## 容量与性能

- 100–110 张 JPEG 帧预计占用约 3–6 MB；四张 RGB565 菜单帧约 1.32 MB，总量限制在 9 MB SPIFFS 可用空间内。
- JPEG 在 PSRAM 中解码到单个 329,728 字节 RGB565 帧缓冲，再整帧推送到 CO5300。
- 实机记录每帧读取、解码和显示耗时；若 10 FPS 不稳定，自动降到 8 FPS，而不是降低到肉眼明显跳帧的 2 FPS。
- 录音缓冲最长 10 秒双声道约 640 KB，放在 PSRAM，与显示帧缓冲并存。

## 验收

- 新待机动画连续回环至少三轮，无重启、缺帧或资源读取错误。
- 三个按钮第一次点击只高亮，第二次点击进入对应功能。
- 实机麦克风录音日志包含非零字节数和合理峰值；静音与说话峰值可区分。
- 网关在线时能创建会话并上传 PCM；离线时显示失败和返回入口。
- 烧录脚本仍只接受与本机 `EXPECTED_MAC` 环境变量一致的目标板。
